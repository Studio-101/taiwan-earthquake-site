# 驗證報告

每個階段完成後，產生一份驗證報告，存到 `docs/reports/phase-N-驗證報告.md`，並在對話中列出。

## 原則

- 每一項都要附上**實際執行的指令或程式輸出**作為證據。不可以只寫「已確認」「通過」。
- 數字必須由程式從資料計算得出，不可以從 `docs/data-notes.md` 抄寫。抄寫的數字只能用來**對照**。
- 和 `docs/data-notes.md` 參考數值不一致的地方，不要修改資料或程式去「湊數字」，直接列出差異讓我判斷。
- 結論只能寫「通過」「不通過」「無法驗證（原因）」三種。

## 每個階段都要檢查

- [ ] 沒有任何生成、補齊或模擬的地震資料（說明資料讀取的程式位置）
- [ ] 畫面或輸出中沒有來源不明的數字、狀態或 Logo
- [ ] 沒有修改 `data/` 裡的原始 XML 檔

## 第一階段（資料轉換）

- [ ] 36 個檔案都有讀到，每個檔案的實際筆數等於 `RecordNumber`
- [ ] 合併後總筆數，並與 `docs/data-notes.md` 的 73,729 筆對照
- [ ] 每年筆數與參考表對照；1999 年與 2024 年應是筆數最多的兩年
- [ ] 每年「超出檔內範圍」的筆數與參考表對照
- [ ] 各年份 Region 是否與參考表一致（1996、1997、1999、2003、2012 年範圍較小）
- [ ] 規模最小值為 3.0
- [ ] 缺值或無法解析的筆數
- [ ] 1999 年最大一筆：1999-09-21 01:47:16，經度 120.816，緯度 23.853，深度 8.0 公里，規模 7.3

## 第二階段之後（畫面）

- [ ] 畫面顯示的點數，等於 CSV 中符合目前篩選條件的筆數（列出計算方式）
- [ ] 座標換算函式：挑 3 筆地震，列出原始經緯度與深度、換算後的座標，並手算驗證
- [ ] 深度方向為 1:1 真實比例；若地形有誇大，倍率有顯示在畫面上
- [ ] 圖例的深度與規模分級，與實際著色邏輯一致
- [ ] 資料來源文字有顯示在畫面上

## 需要我親自檢查的項目

在報告最後列出這一階段需要我用眼睛確認的事項，例如：
- 從東側視角看，台灣東北部外海的地震點是否越往北越深，斜插到地底兩百多公里
- 花蓮外海的密集地震是否落在海上
- 挑一筆大地震，與中央氣象署官網的地震報告對照
